## 环境/工具坑（本仓库复现）

- **`Start-Process -Wait` 会永久挂起**：PowerShell 5.1 的 `-Wait` 会等**后代进程**，而 C# 构建会拉起常驻的 `VBCSCompiler.exe` → 脚本卡死（本次卡了 7 分钟才发现）。**正确写法**：`Start-Process ... -PassThru -NoNewWindow -RedirectStandardOutput $out` 然后 `$p.WaitForExit()`（只等直接子进程）。
- `Start-Process -ArgumentList` 数组传参**不会自动加引号**：`'/p:Platform=Any CPU'` 会被拆成两个参数 → `MSB1008: Only one project can be specified`。直接**省略 Platform**（sln 默认 Debug|Any CPU 就映射到 x64）即可。
- 直接 `MSBuild.exe` 启动会报 `MSB6001 ... Key in dictionary: 'PATH' Key being added: 'Path'`（大小写环境变量冲突）→ 必须加 `-UseNewEnvironment`。
- 本机安全策略仍然：命令含 `msbuild` 字样被拦；`csc.exe` 被拦（"equivalent to Add-Type"）；Bash 里调 PowerShell 被拦；shim 缺 coreutils。
- **`dotnet.exe build` 可以用来跑独立单测工程**（未被拦，`C:\Program Files\dotnet\dotnet.exe`，SDK 6/8/9/10 都在）。`csc.exe` 被拦时这是唯一能编译"临时验证工程"的路子：建一个 `net8.0` 控制台 csproj，用 `<Compile Include="<绝对路径>\ResultFilters.cs" />` 把产品源码链进来，`EnableDefaultCompileItems=false`，然后 `dotnet build` + 直接跑 dll。
- **VS2022 解决方案的 `GetDeploymentPathFromVsixManifest` 偶发 `TypeLoadException: Microsoft.VisualStudio.ExtensionManager.Metadata`** → 这是 VSSDK 目标在"环境不够干净"时的报错；加 `-UseNewEnvironment` 即可（已验证）。另外 MSBuild 偶发内部崩溃 `MissingMethodException: System.__Canon ... IEnumerator\`1.get_Current()`（Expander 里），重试即过，加 `/m:1 /nodeReuse:false` 更稳。

## qgrep — CK1「含注释」注释识别引擎重写（HTML/Razor/Markdown/BAT 等）

- **需求**：`修正bug, 对于.cshtml, .html,.vbchml等HTML文件格式的注释识别不正确,增加智能判断(如//后面的为注释, @*与*@内的也是注释, <!--到-->间的是块注释等),也要能判断出bat, MD等其他文件的注释`
- **原实现的问题**：`CommentSyntax` 只有「一组行注释标记 + 一对块注释 + 一组字符串引号」三件套，无能为力于：
  - `.cshtml/.vbhtml` 被整族丢进 Xml 规则 → 只认 `<!-- -->`，`@* *@`、`//`、`<script>` 里的 JS 注释全都漏判；
  - `.vue` 被塞进 Cpp 规则 → `<template>` 里的 `<!-- -->` 漏判；
  - `.bat/.cmd` 只有行首 `REM` → 漏 `::`、漏 `@rem`；
  - `.md` 完全没有映射 → 整个 Markdown 不做注释过滤；
  - 无扩展名文件（`Makefile`/`Dockerfile`）没有入口。
- **重写内容**（全在 `qgrepControls/Classes/ResultFilters.cs`，`CommentSyntax` 及其下全部重构，对外 API `CommentFilter.IsMatchInComment` 不变）：
  - 规则对象化：`LineCommentRule`（`Marker`/`LineStartOnly`/`NotAfter`/`AllowAtPrefix`/`WordMarker`）、`BlockCommentRule`、`StringRule`（`Open`/`Close`/`Escapes`/`MultiLine`）、`EmbeddedRegion`（`Begins`/`Ends`/`EndAtLineStart`/`Syntax`）。
  - `CommentSyntax` 现在可组合「多行注释 + 多块注释 + 多字符串定界符 + 嵌入区域」，构造时**按标记长度降序排序**（保证 `--[[` 不被 `--` 抢走、`"""` 不被 `"` 抢走、`@"` 不被 `"` 抢走）。
  - 新状态对象 `CommentState{ BlockEnd, OpenString, Region }` 取代原来的 `bool inBlockAtLineStart`，跨行状态可携带「打开的是哪个块注释」「哪个跨行字符串」「当前在哪个嵌入区域」。
  - 判定顺序固定为：**块注释 → 字符串 → 行注释 → 离开区段 → 进入区段**。
  - `EmbeddedRegion` 让 `<script>` 内按 JS、`<style>` 内按 CSS 判定（这才能识别 `<script>/* 块注释 */</script>`）。
  - `CloseRegionIfEnded()`：HTML 解析器不认 JS 注释，`// xxx </script>` 里的 `</script>` 照样闭合脚本区段；在"行注释 / 未闭合块注释 / 未闭合跨行字符串"三条提前返回路径上补做一次区段结束搜索（否则区段会一直开着，后面的 `<!-- -->` 判不出来）。
  - `Html` 的 `//` 带 `NotAfter=":"`，避免把 `https://`、`href=//cdn` 当注释；HTML 的 `"`/`'` 按字符串处理，属性里的 `//` 也不会误判。
- **新增/修正的语言映射**（`SyntaxByExtension` + 新增 `SyntaxByFileName`）：
  - `Html`（`<!-- -->` + `//` + `<script>/<style>`）：`.html/.htm/.xhtml/.shtml/.vue/.svelte/.astro/.hbs/.handlebars/.mustache`
  - `Razor`（+ `@* *@`）：`.cshtml/.vbhtml/.razor`
  - `Aspx`（+ `<%-- --%>`）：`.aspx/.ascx/.master/.ashx/.asmx/.asax/.svc/.asp/.ejs/.erb`

  - `PowerShell`（`#` + `<# #>`）、`Python`（`#` + 三引号跨行）、`Lua`（`--` + `--[[ ]]` + `--[==[ ]==]` + `[[ ]]`）、`Haskell`（`--` + `{- -}`）、`Ini`（`;` + `#`）、`Tex`（`%`）、`Fortran`（`!`）、`Asm`（`;`）、`Jsonc`/`.json5`（按 Cpp）

## qgrep — Add filter 增加「不包含的目录」类型（排除 obj/bin/debug/release 目录）

- **需求**：`在Search configurations窗体中,在Add filter的Type选项中增加一个选项(即不包含的目录, 在Regular expression的选项中要有排除obj目录, 排除bin目录,排除debug目录,排除release目录及同时排除obj及bin目录的选项)`
- **窗体定位**：Search configurations = `qgrepControls/ToolWindows/ProjectsWindow/ProjectsWindow.xaml`；Add filter / Edit filter 对话框 = `RuleWindow.xaml(.cs)`（`RuleType` 下拉 + `RegExTextBox` + 灯泡 `PredefinedPopup`）。
- **关键结论：`.cfg` 只有 path/file/include/exclude/group/endgroup 六种指令**（`qgrep/src/project.cpp:192-236`），未知行会被当**路径**处理，所以**不能新增指令**。目录排除必须写成 `exclude <正则>`。
- **路径形态（决定正则怎么写，非常重要）**：`exclude` 正则在三处以不同形态被匹配：
  | 位置 | 匹配对象 | 形态 |
  |---|---|---|
  | `project.cpp:302` 全量索引 | `traverseDirectory` 回调给的**相对路径** | `obj/x64/Debug/a.cs`（`/` 分隔） |
  | `watch.cpp:46` 文件监听 | 同样相对路径 | `obj/x.cs` |
  | `changes.cpp:52` 增量更新 | **绝对路径** | `c:/proj/obj/a.cs` |
  | `ConfigParser.IsFileRelevant`（C# 侧 FileSystemWatcher） | Windows 原生**绝对路径（反斜杠）** | `P:\proj\obj\a.cs` |
  `fileutil_win.cpp` 的 `traverseDirectoryRec`/`watchDirectory` 与 `fileutil.cpp` 的 `joinPaths`/`normalizePath` 都把 `\` 归一成 `/`，所以引擎侧只有 `config.cpp` 的 `path` 行需要归一化，`exclude` 侧全是 `/`。
- **规格化形式**：目录规则统一写成 **`(^|/)(dir1|dir2)/`**，一个形式同时覆盖上面四种形态（`^` 管相对路径开头，`/` 管绝对路径中段），且 `obj/` 这种带前置分隔符的写法不会误伤 `myobj/`、`/bin/` 不会误伤 `binary/`。
  - re2 侧 `createRegexCached` 用 **`RO_IGNORECASE`**，且 `transformRegexCasefold` 只把字母 casefold（`^|()/` 不变），所以 `Debug/` 能被 `(^|/)(debug)/` 命中。
  - **re2 是 `posix_syntax(true)`**：只能用 egrep 元素（`^ $ . * + ? | () [] {}`），**不能用 `(?:...)` 非捕获组或 `(?i)` 内联标志**。`(^|/)(obj)/` 合法。
  - **不能用 `\\` 表达反斜杠**：`ConfigProject.SaveGroup` 会把规则里的 `\\` 替换成 `\/`（`ConfigParser.cs:320-321`），字面双反斜杠会被吃掉。目录规则只用 `/`，不受影响。
